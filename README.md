# Codex Live Lab

`Codex Live Lab` turns the presentation concept into a challenge-ready live website with two real APIs:

- `OpenAI Responses API` for product ideation and submission copy
- `GitHub REST API` for live repository proof

## Run locally

1. Copy `.env.example` to `.env`
2. Add your `OPENAI_API_KEY`
3. Optionally add `GITHUB_TOKEN` for higher GitHub rate limits
4. Run `npm install`
5. Run `npm run dev`

The Vite client runs on `http://localhost:5173` and proxies API requests to the Express server on `http://localhost:8787`.

## Vercel

This project is set up for Vercel with:

- static frontend build output from Vite
- serverless API routes under `api/**`

Required Vercel environment variable:

- `OPENAI_API_KEY`

Optional Vercel environment variables:

- `OPENAI_MODEL`
- `GITHUB_TOKEN`

## Build and serve

- `npm run build`
- `npm run start`

After a production build, the Express server will also serve the `dist` frontend.

## Required application access

The Express and Vercel API handlers require operator-provided `APP_USERNAME`,
`APP_PASSWORD` (at least 32 characters), and `APP_ORIGIN` (the exact browser
origin, such as `http://localhost:5173` locally). Missing configuration disables
the APIs. Supply these only through private server settings; no application
credential was generated by this change. Use HTTPS for hosted Basic authentication.
Requests are checked before provider calls; browser mutations require JSON and
same-origin requests. Each worker admits at most ten AI requests per minute.
Serverless instances do not share this counter, so production also requires
provider budget controls or a shared quota store. Provider requests have a
30-second timeout, no automatic retries, and a 4,096-token output limit.
The standalone Express listener is loopback-only.
